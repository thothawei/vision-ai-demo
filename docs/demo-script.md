# 5 分鐘面試 Demo 腳本

前置：`ollama serve` 已啟動、`uvicorn main:app` 已啟動、瀏覽器開 http://127.0.0.1:8000，`.env` 的 `API_KEYS` 與前端 `FRONTEND_API_KEY` 一致（見已知限制）。

## 1. 追溯資訊 + 條碼掃描（M1，約 1 分鐘）

1. 在畫面最上方的追溯資訊列填入工單號、料號、批號（例如 `WO-DEMO-001` / `SC-M6-20` / `LOT2026A`），這組資訊之後會自動帶進每一次辨識。
2. 切到「④ 追溯碼辨識」分頁，上傳一張 GS1 條碼標籤照片，講解：條碼解出批號/效期，效期用 GS1 規則換算（YY/DD 特殊規則），已過期直接判 NG、30 天內到期標「即將到期」。

## 2. 外觀瑕疵檢測（M3，約 1 分鐘）

1. 切到「③ 外觀瑕疵異常檢測」分頁，選一個示範類別（`metal_nut`/`screw`/`tile`），上傳一張瑕疵測試圖。
2. 講解：這是非監督式異常檢測（Anomalib PatchCore），只需要良品照片訓練，不需要事先準備 NG 樣本——這正好對應工廠現場「良品多、NG 樣本稀少」的真實情境。
3. 指出熱力圖：紅色區域精準疊在瑕疵位置，AUROC 三個示範類別實測 0.965-0.999（見 CLAUDE.md）。

## 3. 品檢看板 + 人工複判（Phase 9，約 1.5 分鐘）

1. 切到「⑰ 品檢紀錄與看板」分頁，展示折線圖（每日良率）、柏拉圖（NG 原因排行）、堆疊長條圖（各模組良率）。
2. 展開剛剛那筆瑕疵檢測紀錄，若判定有誤，示範「人工複判」把 AI 判的 NG 改成 OK，講解看板即時反映：該模組最終良率上升、AI/人工一致率下降（因為這筆複判結果跟 AI 不一致）——這組數字變化在 Phase 9 開發時有用真實資料交叉驗證過（見 CLAUDE.md 測試紀錄）。
3. 用模組篩選器篩出剛才的模組，講解良率計算刻意排除 `verdict=INFO` 的模組（例如開放式辨識、醫學影像展示），避免看板數字被非品檢判斷汙染。

## 4. 換成貴公司零件怎麼導入（Phase 12，約 1 分鐘）

1. 講解流程圖（見 CLAUDE.md「自有資料導入流程圖」）：
   - 現場誤判 → 人工複判 → `scripts/export_reviewed.py` 匯出成 YOLO/MVTec 格式 → Label Studio Community 人工校正 → 重新擬合/訓練 → 比較新舊 AUROC/mAP50 → 好才換上線。
2. 如果現場有網路，可以打開「③ 外觀瑕疵異常檢測」分頁的「新增自訂類別」，講解：上傳一包良品/NG 照片 zip，背景排隊擬合（不會卡住其他請求），完成後前端直方圖+滑桿可以視覺化調整門檻，即時看誤判率/漏判率的 trade-off——這是實測過的真實數字（bottle 類別 AUROC 0.9977，見 CLAUDE.md）。

## 5. ERP 串接說明（誠實版，約 0.5 分鐘）

1. 講解 `docs/erp-integration.md`：`/api/inspections*` 有 API Key 保護、`since_id` 增量輪詢、NG 立即 webhook 通知（失敗才進佇列重試）、C# 範例。
2. **誠實說明目前的驗證程度**：C# 範例已經用 `dotnet build` 編譯驗證過語法正確，但因為手上沒有真實可連線的 SQL Server 執行個體，沒有實際跑過 `manufacturing-erp` 讀取這支 API 的完整流程；這一步是「介面設計完成、可編譯」而不是「兩個系統已經串接測試過」，避免誇大既有進度。

## 常見面試追問與回答

- **「Ultralytics YOLO 是 AGPL-3.0，怎麼商用？」**：透過網路提供服務（SaaS）需要遵守 AGPL 的開源回饋義務；如果要商用導入，`docs/licenses.md` 有列出查證過、授權較寬鬆（Apache-2.0/MIT）的替代偵測框架候選，正式導入前需要重新評估。
- **「誤判怎麼處理？」**：Phase 9 的人工複判機制——AI 判定跟最終判定分開存，複判會回寫並反映到良率/一致率統計，不會被 AI 的錯誤永久污染紀錄。
- **「沒有 GPU 怎麼辦？」**：全部模型在 CPU 上都能跑（PatchCore 甚至實測 CPU 比 MPS 快，因為 coreset 演算法的逐元素同步問題），YOLO 監督式訓練在 MPS 上也有加速，但沒有的話 CPU 訓練也能跑，只是時間拉長。
- **「NG 樣本太少怎麼辦？」**：M3 異常檢測整條路徑就是為了解決這個問題設計的——非監督式，只需要良品照片；M12/M8-1 這種規則式比對也完全不需要訓練樣本。
- **「這些數字是真的測出來的還是估的？」**：CLAUDE.md 的「測試紀錄」章節，每個 Phase 都有實際跑出來的數字（AUROC、mAP50、耗時），包含中間跑出不合理結果、往下查根因才修正的完整過程（例如 anomalib 內建正規化把分數裁成 `threshold=1.0` 的踩坑紀錄），沒有跑過的地方會誠實寫「未測試」。
